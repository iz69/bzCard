## 運用・互換性の条件

- 処理中の手動修正を抽出完了時に上書きする動作を維持する。補正履歴は独立して保持する。
- Androidを含む既存クライアントの名刺・画像・ジョブAPIのレスポンス形式を維持する。
- 補正履歴・検索・プロンプトは所有者単位。削除も対象利用者・名刺に限定する。
- 外部LINE通信は検証時にmockする。稼働データは読み取り・コピーによる検証に使用する。
- 追加学習や埋め込みモデルの導入は今回の初期実装に含めず、SQLiteによる補正例検索を実装する。

  `integrity_check` はok、`foreign_key_check` は問題なし。2回目の起動でも移行前バックアップが同一。

## 姓・名の補正参照の拡張（2026-10-01）

- 保存された有効なかな補正から、区切りが明確な姓・名の「表記・誤った読み・訂正された読み」を参照。
  例: 須藤 太郎の「すど たろう → すどう たろう」を、別人の須藤 花子にも参考例として利用。
- 別人の氏名全体の読みを流用せず、LLMが同じ誤りを出した部分のみ自動訂正。
  印刷されたかな・ローマ字を最優先し、同一人物の補正を一般的な参考例より優先。
- 複数の確認済みの読みがある表記は、姓・名の一般化から除外。最大3件に絞る前に有効な履歴全体を照合。
